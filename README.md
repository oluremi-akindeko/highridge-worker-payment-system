# Highridge Construction Company Worker Payment System

## Project Overview

This project is a weekly worker payment slip generator developed for **Highridge Construction Company**. It dynamically creates **400 fictional workers**, processes their salary and gender information, assigns employee levels, and generates a weekly payment slip for every successfully processed worker.

The project contains equivalent implementations in **Python** and **R**. Both programs demonstrate variables, lists, loops, conditional statements, exception handling, random data generation, and file operations.

## Business Problem

Highridge Construction Company requires a program to facilitate the weekly payment of its workers. The program must create and process at least 400 worker records and generate an individual payment slip for each worker.

## Project Requirements

The Python and R programs perform the following tasks:

- Dynamically create 400 fictional workers.
- Store all workers in a list.
- Generate a unique ID for each worker.
- Generate a fictional name for each worker.
- Randomly assign a gender to each worker.
- Generate a whole-number weekly salary for each worker.
- Use a `for` loop to process all workers.
- Apply the required employee-level conditions.
- Generate a payment slip for every valid worker.
- Handle potential errors without stopping the entire program.
- Save the generated payment slips to text files.
- Display a processing summary after all workers have been processed.

## Worker Information

Each fictional worker record contains:

- Worker ID
- Worker name
- Gender
- Weekly salary
- Employee level

Worker IDs are generated sequentially from `HC001` to `HC400`.

Worker names are fictional and are generated as `Worker 1`, `Worker 2`, `Worker 3`, and so on. No real employee information is used in this project.

## Employee-Level Rules

The following rules are applied to every worker:

1. If a worker's salary is greater than **$7,500** and less than **$30,000**, and the worker is female, the employee level is assigned as `A5-F`.
2. If a worker's salary is greater than **$10,000** and less than **$20,000**, the employee level is assigned as `A1`.
3. If a worker does not meet either condition, the employee level is assigned as `Unassigned`.

## Overlapping-Condition Decision

The two salary ranges overlap. For example, a female worker earning **$15,000** satisfies both the `A5-F` and `A1` salary conditions.

The program evaluates the `A5-F` condition first because it is the more specific rule and considers both salary and gender. If the worker does not meet the `A5-F` condition, the program evaluates the `A1` condition.

Therefore:

- A female worker earning **$15,000** receives `A5-F`.
- A male worker earning **$15,000** receives `A1`.

The salary comparisons are strict. Salaries equal to the minimum or maximum boundaries do not qualify.

- Exactly **$10,000** does not qualify for `A1`.
- Exactly **$20,000** does not qualify for `A1`.
- Exactly **$7,500** does not qualify for `A5-F`.
- Exactly **$30,000** does not qualify for `A5-F`.

## Sample Payment Slip

```text
Worker ID: HC001
Worker Name: Worker 1
Gender: Female
Weekly Salary: $12,500
Employee Level: A5-F
------------------------------
```

Salaries are stored as whole numbers and displayed with comma separators.

## Python Implementation

### Python Requirements

- Python 3 must be installed.
- Visual Studio Code or another Python-compatible editor may be used.
- No external Python packages are required.

### Running the Python Program

Open the project folder in Visual Studio Code and run:

```bash
python highridge_payment_system.py
```

If the computer uses `python3`, run:

```bash
python3 highridge_payment_system.py
```

### Python Program Output

The Python program will:

1. Generate 400 fictional workers.
2. Store the workers in a Python list.
3. Process each worker using a `for` loop.
4. Assign the appropriate employee level.
5. Display each payment slip in the terminal.
6. Save the completed payment slips in `python_payment_slips.txt`.
7. Display a final processing summary.

Expected summary:

```text

==============================
Total workers: 400
Successful payment slips: 400
Failed payment slips: 0
Payment slips saved in python_payment_slips.txt
```

## Exception Handling

### Python Exception Handling

The Python program uses `try` and `except` to handle:

- Missing worker information
- Incorrect salary data types
- Invalid salary values
- Invalid gender values
- File-writing errors
- Other unexpected processing errors

Exception handling is performed within the worker-processing loop. Therefore, one invalid worker record will not prevent the remaining workers from being processed.

### R Exception Handling

The R program uses `tryCatch()` and `stop()` to handle:

- Missing worker information
- Non-numeric salary values
- Salaries that are not whole numbers
- Invalid salary values
- Invalid gender values
- File-writing errors
- Other processing errors

The R program continues processing the remaining workers when an individual worker record contains an error.

## Reproducibility

The Python program uses:

```python
random.seed(42)
```

The R program uses:

```r
set.seed(42)
```

These instructions allow each program to generate consistent sample data whenever it is run.

Python and R may not generate identical worker records because the two languages use different random-generation methods. However, each program consistently reproduces its own results.
